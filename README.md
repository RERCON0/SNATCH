# SNATCH

Мини-комбайн для скачивания: **yt-dlp + aria2c** в одном инструменте. Две формы — терминальный CLI (`snatch`) и оконное GUI-приложение (`snatch-app`), обе на Rust, без Python и общей зависимости на интерпретатор.

Вставляете ссылку — SNATCH сам определяет, чем её качать (yt-dlp для видео и стримов, aria2c для прямых ссылок, torrent и magnet), спрашивает формат и папку, показывает прогресс и запоминает историю.

## Возможности

- **Авто-выбор движка**: magnet/torrent/прямые ссылки на файлы → aria2c, всё остальное (YouTube и ещё тысячи сайтов) → yt-dlp
- **Форматы для yt-dlp**: лучшее качество, видео до 1080p, только аудио (mp3)
- **Докачка после обрыва**: aria2c работает с `-c` и автоповторами (`--max-tries=10 --retry-wait=2`) — при обрыве просто повторите ту же команду
- **Несколько загрузок CLI одновременно**: до 3 задач по умолчанию, лимит `-j 1..16`; у aria2c до 16 соединений на один HTTP/FTP-файл (`-x 16 -s 16`)
- **История**: последние 15 ссылок и папок подставляются в интерактивном меню
- **Быстрый режим `-y`**: без единого вопроса (только CLI)
- **Авто-установка загрузчиков (Windows)**: GUI предлагает кнопку, CLI — `snatch --install-tools`. Официальные релизы (с проверкой SHA-512 для yt-dlp) сохраняются в `%LOCALAPPDATA%\snatch\bin` — PATH и winget не обязательны

## Две формы

| | `snatch` (CLI) | `snatch-app` (GUI) |
|---|---|---|
| Интерфейс | Терминал, вопрос за вопросом | Окно, поля и кнопки |
| Быстрый режим без вопросов | `-y` + флаги | — |
| Нужен терминал | Да | Нет (двойной клик) |
| Прогресс | Строкой в терминале | Прогресс-бар + журнал |

Обе используют общий движок (`src/engines.rs`, `config.rs`, `tools.rs`) и общий `%LOCALAPPDATA%\snatch\config.json` — история ссылок и папок одна на оба приложения.

## Требования

- Для YouTube/сайтов/torrent: хотя бы один из загрузчиков **yt-dlp** и/или **aria2c** (можно поставить вручную или через встроенную автоустановку)
- **ffmpeg** — только если хотите извлекать mp3 из видео (`-f audio`)
- Для сборки из исходников: **Rust** (stable, `cargo build --release`)

## Установка

### 1. Загрузчики (можно пропустить — оба приложения умеют ставить сами)

Windows (winget):

```powershell
winget install yt-dlp.yt-dlp
winget install aria2.aria2
winget install Gyan.FFmpeg   # опционально, для mp3
```

SNATCH находит binaries в таком порядке: своя автоустановленная копия (`%LOCALAPPDATA%\snatch\bin`) → `PATH` → папки WinGet (`%LOCALAPPDATA%\Microsoft\WinGet\Packages`, `...\WinGet\Links`).

### 2. Сам SNATCH

Соберите из исходников:

```bash
cargo build --release
# -> target/release/snatch.exe     (CLI)
# -> target/release/snatch-app.exe (GUI, ~4 МБ, без терминала)
```

Готовые exe можно положить куда угодно и добавить в `PATH` — установка не нужна.

## Использование

Интерактивный режим (просто запустите и отвечайте на вопросы):

```bash
snatch
```

Сразу со ссылкой:

```bash
snatch "https://youtube.com/watch?v=..."
snatch "magnet:?xt=urn:btih:..."
```

Без единого вопроса (нужны ссылка и папка):

```bash
snatch "https://host/file.zip" -y -o "D:\Downloads"
snatch "https://youtube.com/watch?v=..." -y -o "D:\Video" -f 1080p
snatch "https://host/song.mp3" -y -o "D:\Music" -e aria2
snatch "magnet:?xt=urn:btih:..." "https://host/file.zip" -y -o "D:\Downloads" -j 2
```

Одиночная и параллельная загрузка используют один компактный цветной индикатор: для каждой задачи показываются имя, процент, объём, скорость и подключения; выделение места под торрент отображается отдельной стадией. Если вывод перенаправлен в файл, вместо перерисовки выводятся редкие текстовые снимки состояния без управляющих кодов. Несколько URL запускаются одновременно (по умолчанию не более трёх). В интерактивном режиме `snatch` позволяет вставить сразу несколько ссылок через пробел (пути к `.torrent` с пробелами — в кавычках), один раз выбрать общую папку, затем выбрать движок и формат отдельно для каждой ссылки и подтвердить весь список одной кнопкой. Пустой ввод открывает историю ссылок.

Все флаги:

| Флаг | Что делает |
|---|---|
| `-o, --output <папка>` | Папка сохранения |
| `-j, --jobs <1..16>` | Одновременных загрузок при нескольких ссылках (по умолчанию 3) |
| `-e, --engine {yt-dlp,aria2}` | Движок (по умолчанию — авто-определение) |
| `-f, --format {best,1080p,audio}` | Формат для yt-dlp |
| `--cookies-from-browser <браузер[:профиль]>` | Взять куки из браузера для yt-dlp (chrome, firefox, edge, brave, opera, vivaldi, safari, chromium, whale), например `chrome:Profile 1` |
| `-y, --yes` | Не задавать вопросов (требует url и `-o`) |
| `--clear-history` | Забыть последние ссылки и папки |
| `--install-tools` | Скачать yt-dlp и aria2c в собственную папку SNATCH (Windows) |
| `--version` | Версия |

GUI (`snatch-app.exe`) — двойной клик: вставил ссылку или выбрал локальный `.torrent` кнопкой «файл» (также можно перетащить файл в окно), выбрал движок/формат/папку кликами (встроенный проводник: Дом / Рабочий стол / Загрузки / диски), нажал «Скачать». Прогресс-бар и журнал — во встроенном окне; всплывающие окна закрываются кликом снаружи.

Если `aria2c` пишет, что файлы раздачи уже есть, а файл состояния `.aria2` отсутствует, SNATCH не перезаписывает их: после аварийного завершения это могло бы стереть имеющиеся данные. Для новой загрузки выберите пустую папку. Если нужно сохранить уже скачанные части, сначала скопируйте их и проверьте целостность в торрент-клиенте; не включайте перезапись вслепую.

## Как определяется движок

| Ссылка | Движок |
|---|---|
| `magnet:…`, `.torrent` / `.metalink` файл | aria2c |
| Прямая ссылка на файл (`.mp4`, `.zip`, `.iso`, `.exe`, `.pdf`, …) | aria2c |
| Страницы видео, плейлисты, стримы, всё остальное | yt-dlp |

При выборе yt-dlp для прямой ссылки на файл автоматически подключается aria2c как внешний загрузчик (быстрее и с докачкой).

## Где хранятся настройки

`%LOCALAPPDATA%\snatch\config.json` (Windows) или `~/.config/snatch/config.json` (Linux/macOS). Там живут папка по умолчанию, история ссылок/папок (до 15 записей) и тёмная/светлая тема GUI, общие для CLI и GUI. Очистка истории — флагом `--clear-history` (CLI) или удалением файла.

## Свои пути к загрузчикам

Если yt-dlp/aria2c лежат в нестандартном месте:

```bash
set SNATCH_YT_DLP=C:\tools\yt-dlp.exe
set SNATCH_ARIA2C=C:\tools\aria2c.exe
snatch "magnet:?..."
```

## Если YouTube просит «Sign in to confirm you're not a bot»

YouTube требует авторизацию для части видео (бот-детект, возрастные ограничения, приватные списки). Залогиньтесь в YouTube в своём браузере и передайте его куки:

```bash
snatch "https://youtube.com/watch?v=..." -y -o "D:\Music" -f audio --cookies-from-browser chrome
```

В интерактивном режиме (без `-y`) SNATCH следит за выводом yt-dlp: если сбой похож на требование авторизации («Sign in to confirm you're not a bot», возрастные ограничения, 403 и т.п.), он сам предложит повторить с куками и покажет список браузеров на выбор (в GUI — кнопка «Повторить с куками из браузера»). На обычные ошибки (например, «Unsupported URL») предложение не появляется. Если залогиненный YouTube живёт в отдельном профиле браузера, укажите его: `--cookies-from-browser chrome:Profile 1`.

Куки браузера — это доступ к вашему аккаунту. SNATCH передаёт их только локальному yt-dlp и нигде не сохраняет; но не используйте флаг на чужих машинах.

Закрывать браузер не обязательно, но Firefox при запущенном браузере может держать lock на базе куки — тогда закройте его перед запуском.

## Безопасность

- Никакого shell: дочерние процессы запускаются списком аргументов
- Ссылки с ведущего `-` отклоняются, URL передаётся после `--` — инъекция опций в загрузчики невозможна
- Конфиги самих загрузчиков игнорируются (`--no-conf`, `--ignore-config`) — подложенный `aria2.conf`/`yt-dlp.conf` в текущей папке не сработает
- Поддерживаются только схемы `http`, `https`, `ftp` и `magnet:`
- Бинарники ищутся через собственную автоустановленную папку, `PATH` и папки WinGet (`%LOCALAPPDATA%`): на общей машине это доверие к данным папкам — подменённый `yt-dlp.exe`/`aria2c.exe` будет запущен. При сомнениях задайте точные пути через `SNATCH_YT_DLP`/`SNATCH_ARIA2C`
- Автоустановка проверяет контрольные суммы релизов: SHA-512 для yt-dlp и SHA-256 для архива aria2 — файлы без успешной проверки не устанавливаются
- История ссылок и папок хранится в `config.json` открытым текстом; URL с учётными данными (`https://user:token@…`) попадают туда как есть. На Linux/macOS файл создаётся с правами `0600`. Очистка — `--clear-history`
- Докачка (`-c`): если в папке уже лежит файл с таким же именем от *другой* ссылки, aria2c продолжит писать в него — перед повтором проверяйте имена

## Разработка

```bash
cargo build          # оба бинарника в target/debug
cargo test            # вся тестовая база (валидация ссылок, сборка команд, конфиг, интерактивный флоу)
```

Тесты покрывают валидацию ссылок, сборку команд, обнаружение binaries, устойчивость конфига к битым данным и интерактивный CLI-флоу (предложение куки при auth-сбое, отказ/повтор, порядок валидации перед обнаружением загрузчиков).

### Живой цикл разработки vs глобальная команда на PATH

Rust — компилируемый язык, поэтому здесь нет аналога `pip install -e .`/`uv run`, который читает исходники с диска при каждом запуске. Но для разработки это и не нужно — тот же эффект даёт:

```bash
cargo run --bin snatch       # или --bin snatch-app
```

`cargo run` сам пересобирает при изменениях (инкрементально, обычно секунды) и сразу запускает — не нужна отдельная команда установки.

Если же `snatch` уже стоит глобально на PATH (например, через `cargo install --path .` раньше), эта установленная копия — отдельный, застывший снимок. `cargo build`/`cargo run` её не трогают. Обновить:

```bash
cargo install --path . --bins --force --locked
```

`--locked` — чтобы установка использовала версии зависимостей из закоммиченного `Cargo.lock`, а не переразрешала их заново.
